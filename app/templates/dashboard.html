Create a webhook in Discord
  1. Choose the server and text channel where Hype Bot should post.
  2. In Discord, open Server Settings → Integrations → Webhooks → Create Webhook. Give it a name, select the destination channel, and copy the webhook URL.
  3. You need the Manage Webhooks permission in that server/channel. If you do not have it, ask a server administrator to create the webhook for you or grant the permission.

You do not need to invite a Hype Bot account to your server. Keep the copied webhook URL private; anyone with it can post to that channel.

Connect a Facebook Page

Authorize Hype Bot to publish alerts to a Page you manage.

{{ facebook_page or 'Not connected' }}
Before connecting

Hype Bot can publish to a Facebook Page, not a personal Facebook profile. A Page can represent a creator, hobby, or brand; it does not have to be a business. The Facebook account you authorize must have permission to create content on that Page. Hype Bot currently sends all Facebook alerts to one selected Page.

Don’t have a Facebook Page yet?

You can create a Page for a creator or hobby without turning your personal profile into a business. Your personal profile remains the account you use to sign in and manage the Page.

  1. Sign in to Facebook with the account you plan to connect to Hype Bot.
  2. Open Facebook’s Create a Page screen ↗.
  3. Enter a Page name, choose a category such as Digital Creator if it fits, add an optional description, and create the Page.
  4. Make sure this same Facebook account has access to create content on the new Page. You can review access in Facebook Page access settings ↗.
Steps to create the Meta app
  1. Register for a Meta for Developers account ↗ if you have not already.
  2. From My Apps ↗, choose Create App. On the app-details screen, enter an app name and a contact email associated with the Facebook account you use to manage Pages. Use an inbox you check regularly; Meta may contact you there about the app.
  3. On Use cases, select Manage everything on your Page. In the creation wizard shown here, this Page use case cannot be selected together with Authenticate and request data from users with Facebook Login. The Page management use case is the one Hype Bot needs for Page publishing.
  4. On Business, you can choose I don’t want to connect a business portfolio yet and associate one later. Meta notes that business verification may be required to complete verification and gain data access.
  5. Review the Requirements screen, then review the app name, contact email, and use case on Overview and choose Create app.
  6. In the new app dashboard, open Customize the Manage everything on your Page use case to continue with Page permissions. The callback and permissions are covered below.
  1. Under the Page use case’s permissions, verify that both pages_show_list and pages_manage_posts show Ready for testing. These are the permissions Hype Bot needs to list your Pages and publish posts. Skip unrelated permissions. For a private development test, leave the Actions menu’s Add to App Review option alone; review is for requesting broader access. Then return to the app dashboard, expand Facebook Login for Business in the left sidebar, and choose Settings. Leave Client OAuth login, Web OAuth login, Enforce HTTPS, and Use Strict Mode for redirect URIs enabled. The top Redirect URI Validator only checks a URI; enter this exact callback in Valid OAuth Redirect URIs lower on the page, then choose Save Changes:
{{ callback_url or 'Set APP_BASE_URL in the deployment settings to show the callback URL here.' }}

The callback must exactly match the app's HTTPS address plus /destinations/facebook/callback. In the app's basic settings, copy its App ID and App Secret into META_APP_ID and META_APP_SECRET in Hype Bot's private deployment settings. Meta controls which Pages appear based on the account you authorize. Meta may require app review or an app role before use outside development. Hype Bot must have an HTTPS web address using a domain name; an IP address alone or localhost cannot be used for Meta's redirect. {% elif page == 'hosting' %}

Do you need this?

Discord alerts and YouTube monitoring do not need a public web address. Facebook sign-in does.

What this setup provides

A domain gives Hype Bot a web address. A reverse proxy such as Nginx Proxy Manager (NPM) forwards that address to the app and handles HTTPS certificates. You choose where and how to host Hype Bot; these instructions use NPM as one example.

For Facebook, the address needs HTTPS and a domain name, such as https://hypebot.example.com. An IP address or localhost by itself will not work for Meta authorization.

Nginx Proxy Manager example

Use these steps if you manage your reverse proxy in NPM.

  1. Choose the web address.

    Use a domain you control, such as hypebot.example.com. Replace the example with your own address.

  2. Point the domain to your network.

    Your main website can stay hosted elsewhere. If an existing hostname such as home.yourdomain.com already points to NPM, create a CNAME for the new Hype Bot subdomain (Host/Name hype, Target home.yourdomain.com). Alternatively, create an A record for hype using the same public IPv4 address as home. Do not change the main domain or existing home record, and never use a private LAN IP such as 192.168.x.x in public DNS. Wait for DNS to resolve before requesting an HTTP-validated certificate.

  3. Add a Proxy Host in NPM.

    Open the NPM page. Choose Hosts → Proxy Hosts → Add Proxy Host. On the Details tab, enter:

    • Domain Names: your Hype Bot domain. This is the address you type in your browser.
    • Scheme: http.
    • Forward Hostname / IP: the LAN IP of the computer running Hype Bot, reachable from the NPM host (do not use localhost when NPM is on another computer).
    • Forward Port: 8018 for the project's Debian Docker command. This is the host port that forwards to the app's internal port 8000.

    For Access List, choose a list that allows your VPN users. Do not choose Publicly Accessible for a private dashboard. Turn on Block Common Exploits. Leave Cache Assets and Websockets Support off, then select Save. If NPM runs on another computer from Docker Desktop, publish the app on a LAN-reachable port (for example, 8018:8000, not 127.0.0.1:8018:8000) and use the desktop LAN IP. Restrict inbound port 8018 with the desktop firewall so only the NPM host can reach it; do not forward this port from the Internet.

  4. Add HTTPS.

    Find the new Proxy Host, open its three-dot menu, choose Edit, then open the SSL tab. Select an existing certificate for this exact domain, or request a Let's Encrypt certificate. Enable Force SSL if available, then save.

    For a new certificate using the default HTTP validation, public DNS must point to your network and inbound port 80 must reach NPM for certificate validation and renewals. Keep Hype Bot's host port 8018 private; do not forward that port from your router to the Internet. DNS-based certificate validation may be an option if your DNS provider and NPM setup support it.

  5. Tell Hype Bot its HTTPS address.

    In the private .env file used to start the app, set APP_BASE_URL to https:// plus the same domain, with no trailing slash. Set COOKIE_SECURE=true. Recreate the container so it loads the new settings, keeping the hype-bot-data volume.

  6. Check the setup.

    While connected to your VPN, open https:// plus your domain and sign in. Then return to the Facebook page. The callback shown there must match the URL entered in Meta, followed by /destinations/facebook/callback.

Keep it privateUse your VPN-only NPM Access List or an equivalent firewall rule to limit who can open the dashboard. The certificate validation port is separate from Hype Bot's private app port.

NPM labels can vary slightly between versions. If your proxy runs on another computer or in a different Docker network, the Forward Hostname / IP value may differ from this example. See the NPM guide ↗ for the manager itself.
