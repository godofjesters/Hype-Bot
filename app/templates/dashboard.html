{% elif page == 'facebook_setup' %}

Facebook is optional and takes several setup steps

Hype Bot works without Facebook. You can monitor YouTube channels and send Discord alerts without creating a Facebook Page or Meta developer app. Skip this guide if you do not need Facebook posting.

Facebook posting is to a Page, not a personal profile. Setup involves Meta app configuration, Page permissions, and an HTTPS domain. Meta can change its screens and may require app review or business verification for use beyond development.

Before you start

Gather these pieces first so setup goes smoothly.

  • A Facebook Page. It can represent a creator, hobby, or brand; it does not have to be a business. If you need one, create a Page on Facebook ↗.
  • The Facebook account you authorize must be able to create content on that Page. If the Page is linked to a Meta business portfolio, your account also needs a role in that business.
  • A domain-based HTTPS address for Hype Bot. An IP address by itself or localhost will not work as Meta's OAuth redirect. Keep the dashboard private with a VPN, firewall, or equivalent access control; the domain does not require making the app publicly accessible.
  • Access to Hype Bot's private deployment settings so the Meta App ID and App Secret can be added without sharing them in chat or logs.

If the HTTPS domain or proxy is not ready, follow the Hosting & HTTPS guide → first.

Step 1 · Create the Meta app

Use an app that you control and can maintain.

  1. Open Meta for Developers → My Apps ↗ and choose Create App. Sign in with the account that manages your Page.
  2. On App details, enter an app name and a contact email associated with the Facebook account you use to manage Pages. Use an inbox you check regularly; Meta may contact you about the app.
  3. Under Use cases, choose Manage everything on your Page. In the creation wizard confirmed for this guide, this cannot be selected together with Authenticate and request data from users with Facebook Login. Choose the Page use case for Hype Bot publishing.
  4. Under Business, you can choose I don't want to connect a business portfolio yet and associate one later. Meta says business verification may be required for data access.
  5. Review Requirements and Overview, then choose Create app. In the dashboard, open Customize the Manage everything on your Page use case.
  6. Keep the app in development while setting it up. Add the Facebook account you will use to authorize as an app administrator, developer, or tester if Meta requires an app role.

Step 2 · Enable the required permissions

In the app's Page use case, verify the publishing permissions are ready for testing.

  • pages_show_list — lets Hype Bot list Pages available to your account.
  • pages_manage_posts — lets Hype Bot publish Page posts.
  • business_management — needed for Pages linked to a Meta business portfolio. Your Facebook account also needs a role in that business.

For this private development setup, pages_show_list and pages_manage_posts should show Ready for testing. Enable business_management for testing when listing Pages linked to a business portfolio. Meta may require review or verification before use outside development roles. Leave Actions → Add to App Review alone unless broader access is needed. Do not add unrelated permissions.

Step 3 · Register the exact HTTPS callback

This value must match Hype Bot's configured HTTPS address exactly.

  1. In the Meta app dashboard, open Facebook Login for Business → Settings.
  2. Leave Client OAuth login, Web OAuth login, Enforce HTTPS, and Use Strict Mode for redirect URIs enabled.
  3. Enter the callback below under Valid OAuth Redirect URIs, then choose Save Changes. The Redirect URI Validator near the top only checks a URL; it does not register the callback.
{{ callback_url or 'Ask the Hype Bot administrator to set APP_BASE_URL before continuing.' }}

The callback is Hype Bot's HTTPS base address plus /destinations/facebook/callback. It must match exactly, including scheme and hostname.

Step 4 · Configure Hype Bot

The App Secret is a credential. Keep it private.

  1. In Meta's App settings → Basic, copy the App ID and reveal/copy the App Secret.
  2. Ask the person who runs Hype Bot to set META_APP_ID and META_APP_SECRET in the private deployment environment. Never paste the App Secret into this page, a screenshot, a support post, or a chat.
  3. Make sure APP_BASE_URL is the same HTTPS address you will open in the browser, with no trailing slash. Set COOKIE_SECURE=true when using HTTPS.
  4. Recreate or restart the container so it loads the settings, while keeping the existing named data volume.
  5. Open Hype Bot at that HTTPS address on a device that can reach it (for a private installation, connect to the VPN first).

Step 5 · Authorize and choose Pages

Meta presents separate choices for business portfolios and Pages.

  1. In Hype Bot, open Facebook notifications → and choose Authorize with Meta.
  2. Sign in to the Facebook account with access to the Page. If Meta asks which businesses Hype Bot may access, choose Current Businesses only, then select only the business that owns or manages the Page you need.
  3. When Meta asks which Pages to share, choose Current Pages only and select the Page or Pages Hype Bot should be allowed to use. Continue and accept the requested Page permissions.
  4. After Meta returns to Hype Bot, use the Page dropdown and Use this Page to select the destination.
Current limitationHype Bot stores one global Facebook Page selection. All Facebook alerts go to that Page. Per-channel routing between business and personal Pages is planned but is not available yet.

Step 6 · Confirm the connection

A test post is optional and visible on the selected Page.

  1. Confirm the Facebook page in Hype Bot shows the selected Page as connected.
  2. If you want to verify publishing, choose Publish test post. This creates a real Facebook post; skip it if you do not want a test post on the Page.
  3. Check the Hype Bot Activity page for delivery status after an actual alert.

If something goes wrong

Check the setting that matches the symptom.

  • A business Page is missing: verify business_management is enabled for testing, the authorizing account has a role in that business, then authorize again and select the business and Page.
  • Meta reports an invalid scope: make sure the permission is added to the app's Page use case and ready for testing, then retry authorization.
  • Meta returns a redirect error: compare the registered Valid OAuth Redirect URI with the exact callback shown above and verify APP_BASE_URL.
  • The callback cannot load: use the HTTPS domain, not the LAN IP. If Hype Bot is VPN-only, the device completing sign-in must be connected to a network path that can resolve and reach that domain.
  • Authorization completes but the Page cannot publish: verify the Facebook account has content-creation access to that Page and pages_manage_posts is ready for testing.
{% elif page == 'hosting' %}

Do you need this?

Discord alerts and YouTube monitoring do not need a public web address. Facebook sign-in does.

What this setup provides

A domain gives Hype Bot a web address. A reverse proxy such as Nginx Proxy Manager (NPM) forwards that address to the app and handles HTTPS certificates. You choose where and how to host Hype Bot; these instructions use NPM as one example.

For Facebook, the address needs HTTPS and a domain name, such as https://hypebot.example.com. An IP address or localhost by itself will not work for Meta authorization.

Nginx Proxy Manager example

Use these steps if you manage your reverse proxy in NPM.

  1. Choose the web address.

    Use a domain you control, such as hypebot.example.com. Replace the example with your own address.

  2. Point the domain to your network.

    Your main website can stay hosted elsewhere. If an existing hostname such as home.yourdomain.com already points to NPM, create a CNAME for the new Hype Bot subdomain (Host/Name hype, Target home.yourdomain.com). Alternatively, create an A record for hype using the same public IPv4 address as home. Do not change the main domain or existing home record, and never use a private LAN IP such as 192.168.x.x in public DNS. Wait for DNS to resolve before requesting an HTTP-validated certificate.

  3. Add a Proxy Host in NPM.

    Open the NPM page. Choose Hosts → Proxy Hosts → Add Proxy Host. On the Details tab, enter:

    • Domain Names: your Hype Bot domain. This is the address you type in your browser.
    • Scheme: http.
    • Forward Hostname / IP: the LAN IP of the computer running Hype Bot, reachable from the NPM host (do not use localhost when NPM is on another computer).
    • Forward Port: 8018 for the project's Debian Docker command. This is the host port that forwards to the app's internal port 8000.

    For Access List, choose a list that allows your VPN users. Do not choose Publicly Accessible for a private dashboard. Turn on Block Common Exploits. Leave Cache Assets and Websockets Support off, then select Save. If NPM runs on another computer from Docker Desktop, publish the app on a LAN-reachable port (for example, 8018:8000, not 127.0.0.1:8018:8000) and use the desktop LAN IP. Restrict inbound port 8018 with the desktop firewall so only the NPM host can reach it; do not forward this port from the Internet.

  4. Add HTTPS.

    Find the new Proxy Host, open its three-dot menu, choose Edit, then open the SSL tab. Select an existing certificate for this exact domain, or request a Let's Encrypt certificate. Enable Force SSL if available, then save.

    For a new certificate using the default HTTP validation, public DNS must point to your network and inbound port 80 must reach NPM for certificate validation and renewals. Keep Hype Bot's host port 8018 private; do not forward that port from your router to the Internet. DNS-based certificate validation may be an option if your DNS provider and NPM setup support it.

  5. Tell Hype Bot its HTTPS address.

    In the private .env file used to start the app, set APP_BASE_URL to https:// plus the same domain, with no trailing slash. Set COOKIE_SECURE=true. Recreate the container so it loads the new settings, keeping the hype-bot-data volume.

  6. Check the setup.

    While connected to your VPN, open https:// plus your domain and sign in. Then return to the Facebook page. The callback shown there must match the URL entered in Meta, followed by /destinations/facebook/callback.

Keep it privateUse your VPN-only NPM Access List or an equivalent firewall rule to limit who can open the dashboard. The certificate validation port is separate from Hype Bot's private app port.

NPM labels can vary slightly between versions. If your proxy runs on another computer or in a different Docker network, the Forward Hostname / IP value may differ from this example. See the NPM guide ↗ for the manager itself.

Backup and restore

Download your saved Hype Bot data or restore it on this installation.

What the backup contains

Channels, detected events, delivery history, dashboard settings, message templates, and encrypted Discord/Facebook credentials. It does not contain your .env file or environment settings, including APP_SECRET, APP_ENCRYPTION_KEY, YouTube API key, or Meta app credentials.

When moving to another server, configure its .env separately. Use the same APP_ENCRYPTION_KEY so the saved Discord and Facebook credentials can be decrypted. Keep the backup file private because it contains encrypted credentials.

The current database is saved automatically in /data/backups before it is replaced. Restore accepts backups up to 100 MB and requires the matching APP_ENCRYPTION_KEY.
